孤儿注册表清理

孤儿注册表项 = 注册表里 ContentDir 指向的目录已不存在的项 （常见于库被移动/删除/改名后）。
判定只认「ContentDir 非空 且 目录不存在」； ContentDir 为空的项不会被删（可能是别的 NI 产品）。
删除前会把 三视图的值 + Content\k2lib* 条目 + Service Center XML + Native Access 记录 全部备份到 data\orphan-backups\<时间戳>\，可随时一键还原。

重复内容检测

库关系：按 NKI 名称集合判定两库关系，分「完全重复 / 完整包含 / 版本升级」三种常见情形并给出操作建议。
重复大文件：按内容指纹找出完全相同的文件（默认 ≥5 MB）。检测只读，不会删除任何文件。
点上方按钮开始检测

③ 入库管理

                        

                            
                            
                            
                                                         
                        

                    

                    

                        入库 = 完整写入 Kontakt 读取的全部位置：
                        ①②③ 注册表三视图（HKLM 64/32 位 + HKCU）、
                        ④ Service Center 记录 <键名>.xml、
                        ⑤ 便携版库列表（Settings.cfg + LibraryHints.xml）。

                        元数据取自各库自带的 .nicnt；无 .nicnt 的旧式库会回退使用
                        注册表 + LibraryHints 中的信息补齐 Name/SNPID。
                        本工具不修改 .nicnt、不伪造授权字段、不绕过任何授权校验。

                        便携版写入前会自动备份（*.klm-backup-*），写后校验，失败自动还原；入库时请确保 Kontakt 已完全关闭。
                    

                    

                    

                


                

                    

                        
④ 版本兼容检查

                        

                    

                    
读取每个库内 NKI 头部记录的 Kontakt 引擎版本，与当前设定的 Kontakt 版本比较，提示无法加载的库。

                    

                


                

                    

                        
⑤ AI 助手（说明书问答）

                        

                            
                            
                        

                    

                    

                        填写任意 OpenAI 兼容端点即可（DeepSeek / OpenAI / SenseNova / Ollama / LM Studio…）。

                        Agent 的工作方式：把说明书拆解成本地知识库（文字抽取 + 图片页视觉解读）→ 本地检索 → 只把相关片段交给模型 → 回答并标注页码，你问到的地方可直接调出原页例图。
